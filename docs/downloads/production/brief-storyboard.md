# 把一個概念，拆成可製作的分鏡

從教學目標、生活比喻到逐幕講稿；先把要懂的事說清楚，再決定畫面。

技術文章；不代表新影片。更新：2026-10-23。

## 先定義觀眾要懂的一件事

一分鐘是聚焦的尺度，不是塞滿術語的理由。演算法第一集曾把效率比較與五大特性混在一起，後來聚焦成「清楚、做得到、會結束」的步驟概念；效率留給其他課程。

提問只補缺少的資料：核心目標、先備知識、情境、風格、片長、聲音、字幕與素材。已有確認的選擇繼續沿用。

## 把畫面、動作和講稿放在同一張表

分鏡至少寫出規劃秒數、教學意圖、物件的前後狀態、畫面重點字及完整旁白。標示哪些數字是實際示範、哪些是計算結果。

先提供具體可審查的製作單，再依當次授權進入製作。歷史對話曾逐集確認新講稿；這不表示每次修小字或再次預覽都要重新確認。

```text
BRIEF.md       核心目標、受眾、範圍、風格
STORYBOARD.md  時間、畫面、動作、旁白
SCRIPT.md      要讀出的完整講稿
SOURCES.md     素材來源與使用條件
```

## 把設計決定留下來

同系列的角色、場景、色彩、聲音與術語寫入文件，後續集數才可重用。演算法延續黏土廚房，Scratch 延續紙雕 RPG，排序與搜尋延續深藍圖表。這些是案例選擇，不是所有主題都要套同一種動畫風格。

## 可重複的步驟

1. 先寫一句學習目標與不包含的內容
2. 提出一個能解釋概念的生活或遊戲情境
3. 逐幕填好畫面、狀態、旁白與暫定時間
4. 按當次授權確認製作範圍，保存為製作文件

## 可複用提示詞

```text
請先閱讀工作區與目標專案的 AGENTS.md、README、版本設定及既有審查紀錄，沿用已確認需求。區分規劃、已生成、已驗證與未完成；保留原素材及歷史輸出。只執行本次指定階段，不因有提示詞而自行消耗配音額度、渲染或發布。對已授權事項不要重複詢問。

這次只做需求與分鏡，主題為【主題】，看完要理解【單一目標】。
專案位置：【專案路徑】。已確定：【既有選擇】；還沒確定：【待選項】。
以生活或遊戲例子說明，先提供風格選項與逐幕表：規劃時間、教學目的、物件前後狀態、畫面文字及完整繁中旁白。
明確標記示意、縮時及計算結果。檢查容易混淆的術語與既有單元關聯。
本次先不生成媒體或正式影片；交付 BRIEF、STORYBOARD、SCRIPT 與待決問題。
```

## 驗收

- 能用一句話說出本集目標
- 分鏡的每個動作都有教學用途
- 講稿與畫面沒有互相矛盾
- 規劃秒數明確標示為暫定

常見問題：把一分鐘當作硬性字數配額，或尚未釐清概念就先生成大量素材。
